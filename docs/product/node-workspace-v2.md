# 节点资产工作区 v2

状态：目标交互与验收规范，不代表全部实现。更新：2026-09-24。

本文把[节点编辑器交互设计 v1](node-editor-ux.md)的节点探索、执行溯源和质量呈现要求落实为完整工作区。涉及画布配置位置、面板职责和输入操作时，以本文的 v2 目标为准；v1 的执行状态词汇、复用确认、证据和质量边界继续适用。系统正确性仍以 [Pipeline 契约](../design/pipeline-contract.md)和[通用 DAG 编排](../design/generic-dag-orchestration.md)为准。

## 1. 产品目标

这是公司内部制作、调试和复用资产流水线的核心工具。操作者围绕节点工作：提供输入，在节点上选模型、改参数，看中间结果，决定下一步，再执行。工作台必须让人从画布直接完成这些操作。

UE 蓝图是交互参考：可阅读的数据流、在节点上下文修改值、选中对象后看到完整属性、持续可见的运行工具和问题定位。此参考不改变资产流水线的数据模型，也不要求增加通用变量、控制流语言或任意参数连线。

整体交付必须包括输入节点、计算节点、Details、预览、运行工具栏、运行记录六个相互协作的部分。仅调整主题、节点尺寸、侧栏顺序或增加通往原长表单的按钮，不构成 v2 完成。

## 2. 现有交互的结构问题

以下是本次设计基于现有实现的观察，不是对已支持能力的否定：

- `main.tsx` 中的画布节点主要展示实例名、算子与端口，值和模型配置依赖侧栏。
- `ExecutionPanel.tsx` 同时负责输入上传、执行范围、启动、预览、历史、复用、人工审查和重试，核心操作分散在长面板中。
- 图输入有契约编辑入口，但操作者给图片、文本等实际值的入口在运行区域；画布与实际输入脱节。
- 参数草稿、编译、预检、运行恢复已有保护机制；改造必须保留这些语义，不能靠绕过保护缩短流程。

目标是重组完整操作路径。已有输出比较、质量证据、人工决定和允许动作应迁移至相应工作区，不再复制一套平行能力。

## 3. 固定工作区

```text
┌ 草稿名称 · 保存状态 ─ 检查状态 ─ 执行范围 ─ 启动运行 ─ 运行记录 ┐
│                         画布（默认占满工作区）                 │
│              输入值 → 分割 → 提取 → 生成 → 发布                │
│                 节点内直接选模型、改常用参数                   │
│   [节点库按需浮层]                         [Details 按需浮层] │
├───────────────────────────────────────────────────────────────┤
│ 所选节点预览 · 运行来源 · 输出端口 · 新鲜度 · 比较（按需展开） │
└───────────────────────────────────────────────────────────────┘
```

- 顶部始终可见；启动不依赖打开「运行」页签或滚动到面板某处。
- 画布是默认主区域并占满工作区；节点库和 Details 按需浮在画布上方，均可收起，Details 可调整宽度。打开辅助面板不能缩小或重排管线画布；收起面板不能清空选择、输入、参数或预览来源。
- Details 跟随所选节点。无选择时显示简短画布摘要及操作提示，不显示所有节点的配置长表单。
- 运行记录是独立抽屉或底部面板。打开记录不改变当前草稿；查看历史配置为只读，需显式「载入为草稿」才改变编辑对象。
- 预览与运行记录分别可见。不能用「看历史」和「配置节点」的互斥页签让预览、选中节点和输入上下文消失。
- 默认 1440×900 和 1920×1080 桌面视口下，启动、当前选择、节点配置和预览来源无需页面级滚动即可找到。窄视口允许收起辅助面板，不能遮挡启动和错误提示。

## 4. 输入节点必须持有实际值

管线输入节点显示「输入名称、数据类型、实际值/缩略图、来源、状态、修改入口」，右侧只有真实输出端口。契约编辑收进 Details 的高级部分；主操作是给值。

| 输入类型 | 节点内默认控件 | 已绑定后的显示 |
| --- | --- | --- |
| RGB / RGBA 图片 | 点击上传或拖入文件 | 缩略图、文件名、替换/清除 |
| 文本 | 多行文本框 | 当前文本与应用状态 |
| mask | 上传与兼容历史结果选择 | 缩略图、来源信息 |
| 多视图观测 | 添加多张图片 | 视图数量、有序缩略图、管理入口 |
| 其他已支持 Artifact | 选择兼容历史结果 | 来源运行、节点、输出名称 |

具体类型能力由现有输入 API 和契约决定。没有专用编辑器的类型明确说明支持的来源；不能渲染一个无作用的通用文本框。

行为要求：

1. 上传成功前显示上传中；失败显示原因与重试。成功后显示可核验引用，且说明上传尚未执行模型。
2. 图片路径与 Artifact ID 仅在高级入口展示。正常路径不要求手填内部标识。
3. 历史结果选择器只展示兼容候选；选择时绑定精确的运行、节点和输出。预览某结果不等于选用它。
4. 输入修改或替换后，依赖节点的结果显示需要更新，当前预检作废。原运行输入和输出保持不变。
5. 每个输入独立保存值与状态。更改执行范围为「运行到这里」不能清空无关输入；返回完整图仍有原值。
6. 同一输入的上传响应必须核对输入身份及本次请求版本。晚到的旧上传不得覆盖新值；删除、改名或替换模板后不得把旧上传绑定到另一个输入。
7. 保存草稿若尚不保存实际输入，保存反馈必须直说「已保存图和参数；实际输入未保存」，重新打开时显示需要重新提供。不得暗示整个工作区已恢复。

输入数据绑定属于执行准备状态，不塞入 Operator 参数或改写 `pipeline.inputs` 契约。管线导出 YAML 继续描述图及契约，不包含上传文件内容。

## 5. 计算节点的可操作结构

每个节点采用稳定顺序：标题与实例名 → 模型/实现 → 常用参数 → 数据端口 → 简短结果或问题摘要。

- 标题显示操作者可理解的功能名称；实例 ID、版本和内部实现名在 Details 可查。
- 有多个兼容模型时，节点内直接提供模型下拉；只有一个时显示已绑定模型。无可运行实现时显示具体原因和配置入口。
- 模型选择只列出实现当前 Operator 的候选。不能跨不同 Operator 偷换契约。无模型的处理节点无需空的「模型」控件。
- 高频参数直接编辑；完整参数在 Details。节点内默认展示少量最相关字段，展开不会改变参数值。
- 高频字段必须来自当前实现的参数 schema；展示优先级可由前端元数据决定，但元数据不能另定义类型、范围、默认值或枚举。
- 所有未在节点内展示的可编辑参数，必须能在 Details 找到。不能只支持模板中预先写死的几个模型。
- 固定部署值显示为只读，明确来源；不能显示成可自由调节的生成参数。
- 错误摘要告诉用户缺少哪个输入、哪个参数不合法或哪个绑定不可用，并可定位控件。
- 节点上的状态明确标注来源运行；历史成功徽标不能让当前已改动配置看起来已经执行。

例如真实契约允许时，分割节点显示模型和阈值；文字提示由文字输入节点连接到真实 `text` 端口。Shape 节点显示模型及其实际 schema 提供的常用生成参数。不要给所有模型硬塞 seed、步数或分辨率。

切换模型使用现有受信绑定逻辑：处理固定部署覆盖，重新编译，指出原参数中不适用的字段；不得静默删除用户普通参数。存在未应用参数时，应先在原地应用或放弃，再切换模型。

## 6. 参数属性与数据端口必须分清

| 概念 | 权威来源 | 交互 | 持久化位置 |
| --- | --- | --- | --- |
| 输入/输出数据端口 | OperatorSpec | 节点边缘的连接点和连线 | `nodes.*.inputs` 引用 |
| 模型/实现选择 | Registry 与绑定规则 | 节点及 Details 的选择器 | `backend` / `adapter` |
| 处理参数 | 实现参数 schema | 文本、数字、枚举、布尔及结构控件 | `nodes.*.parameters` |
| 管线输入实际值 | 输入 API 与 Artifact 契约 | 输入节点中的上传/输入/选择 | 执行输入引用 |

参数字段没有连接点，不接受拖线。只有 OperatorSpec 已声明的数据输入才是 pin。即使某个参数叫 prompt 或 image，也不能仅凭名字变成数据端口。

若未来希望 seed、模型或任意参数可连线，必须先设计明确的值 kind、转换或参数化 Operator 契约；本次不增加这些能力。现有 kind、schema、cardinality、frame 和 unit 的校验继续由后端负责；前端兼容提示仅作及时反馈。

端口默认显示名称和可读类型，详细 schema/frame/unit 放在悬浮说明与 Details。不能为了界面简洁隐藏不兼容原因，也不能自动插入隐式转换。连接已有输入时应清楚展示替换对象；画布内编辑数字、下拉和文本时不能触发拖动、节点删除或连线。

## 7. 节点与 Details 共享一份配置

Details 默认包含：节点说明、模型/实现、完整参数、数据连接、该节点结果摘要；内部身份和原始 JSON 折叠到高级区域。

- 节点控件与 Details 是同一份配置的两个视图。任一处编辑立即反映到另一处，包括尚未应用的字段、错误与恢复默认动作。
- 保持既有字段应用规则：有效标量可在失焦或 Enter 时应用，Esc 放弃当前字段未应用编辑；输入法组合期间 Enter 不触发应用。枚举/布尔选择即应用；数组/对象及完整 JSON 显式应用。有效值应用后自动触发编译。界面不要求用户手动编译。
- 非法数值或未应用 JSON 保留原文及错误，不能回退显示旧值造成输入被吞掉的错觉。
- 节点切换、Details 收起、运行记录开关都不得丢失未应用内容。
- 运行按钮展示阻塞原因与可定位的节点列表；原有运行恢复不受当前草稿未应用参数干扰。
- 默认值必须区分「沿用实现默认值」与「用户覆盖」。移除覆盖恢复默认语义，不能把默认值复制成用户参数。
- 同步使用节点 ID 和字段标识，不能通过扫描 DOM、模拟点击或另建隐藏表单通信。

## 8. 预览是持续的工作上下文

单击节点后，预览区域展示这个节点在所选运行的输出。选择输入节点时展示当前实际输入；历史输入需带来源说明，不能与当前草稿值混淆。

预览标题始终能回答四件事：哪个运行、哪个节点、哪个输出、是否对应当前配置。没有输出时按实际情况显示尚未运行、正在运行、等待人工、执行失败或这个输出不支持可视预览；不得用通用空白代替。

- 图片、mask、网格使用现有预览能力；不可视数据展示结构化摘要及下载入口。
- 多输出时选择端口；更换节点后不沿用不属于该节点的旧端口。
- 修改参数保留旧预览并标记需要更新；绝不把它替换成空白，也不重标成新配置结果。
- 预览可放大、收起、恢复，且保持运行与节点关联。昂贵三维渲染按需加载，不在每个节点同时创建渲染器。
- A/B 比较保留每份结果的模型、运行和输出来源。「用作下游输入」是独立动作，需后端核验并产生新运行。
- QA、执行状态、人工决定和资产边界分开展示；成功不代表质量合格，未评估不得显示为通过。

## 9. 顶部运行工具栏

工具栏固定显示：执行范围、检查状态、主要执行动作、运行记录入口。检查中的状态与阻塞原因可展开定位，但不会把内部日志塞进主工具栏。

| 场景 | 主动作与说明 |
| --- | --- |
| 当前图可执行 | 启动新运行；一次点击进入创建流程 |
| 输入缺失 | 启动受阻；定位对应输入节点 |
| 参数未应用或不合法 | 启动受阻；定位字段并应用/放弃 |
| 配置检查中 | 显示正在检查当前配置 |
| 运行到所选节点 | 显示目标名与祖先范围，预检后确认 |
| 复用历史节点 | 列出将执行/复用/受阻节点，核验后确认 |
| 当前运行等待人工 | 明确人工待办入口；不伪装成再次启动 |

普通新运行不增加多余确认步骤。复用及子图保留现有明确范围确认和启动摘要复核。服务绑定成功不等于远端服务可达或 GPU 空闲；没有探测结果时不能标为「服务在线」。

运行到节点仅检查目标与祖先，未选分支不能阻止执行。修改目标不得丢失整个图的输入。预检、启动仍使用完整身份与摘要保护；重复点击不得产生意外重复运行。

## 10. 运行记录与恢复

运行记录默认展示运行标识、状态和已有来源信息。时间、模型、输入摘要仅在服务提供时展示，不在客户端推断历史事实。

选中历史运行会更新预览与历史状态层，不覆盖当前图。顶部持续说明「正在查看运行 X；下次执行使用当前草稿」。查看历史图需明确只读；载入为草稿是独立动作，覆盖有改动的草稿前保护用户编辑。

失败、中断、证据受阻分别展示，按后端允许动作提供重试、恢复或处理上游入口。执行日志、attempt 和摘要进入该运行的详情，不夹在配置控件中。人工审查保持可直接打开、明确提交与收起的区别，不能因为面板重构丢失待办。

## 11. 实现边界

本次允许重组组件和提升共享状态，不引入新编排系统。建议将执行输入、所选运行、创建状态和现有执行命令集中到工作区控制层，再由节点、工具栏、Details、预览和运行记录消费。输入状态不能继续私有封装在一个只能通过页面布局访问的长表单中。

保持现有 API、Pipeline/Artifact/BuildRun 身份及证据语义；UI 状态不写入 OperatorSpec 或实际参数。新增持久化字段需要单独契约与往返测试。GPU 任务仍串行；多租户、分布式调度、协同编辑、完整 FrameGraph 和自动物理属性估计均不属于本次交付。

## 12. 完整验收门槛

以下用真实浏览器操作验收；单元测试和截图不能单独替代交互回放。每项记录已执行环境、结果及未验证边界。

| 编号 | 操作 | 必须观察到的结果 |
| --- | --- | --- |
| V2-01 | 打开 CPU 图片模板，在画布输入节点上传图片并启动 | 不打开长运行表单即可得到输出预览/下载；上传前后状态准确 |
| V2-02 | 直接在处理节点修改 schema 中的高频参数 | Details 同步；编译更新；CPU 输出对应新参数 |
| V2-03 | 在节点输入非法数值，再切节点和面板 | 原文和错误保留；启动明确受阻；修正后可执行 |
| V2-04 | 从节点选择兼容模型 | Details 与绑定一致；不保留错误固定部署覆盖；参数错误可定位 |
| V2-05 | 给图片和文本两个输入分别赋值 | 值属于各自节点；文本经真实数据端口传递；上传互不覆盖 |
| V2-06 | 切换完整图/运行到这里/完整图 | 无关输入仍保留；子图仅执行目标与祖先 |
| V2-07 | 修改已出结果节点参数 | 旧预览继续可见且标为需要更新；执行/QA 状态不混淆 |
| V2-08 | 查看另一次运行，再返回配置 | 历史查看不覆盖草稿；预览来源明确；后续执行目标可辨认 |
| V2-09 | A/B 比较并显式选用某输出 | 选用对象明确；预览切换不自动绑定；复用经过后端核验 |
| V2-10 | 运行等待人工或失败/中断 | 对应审查或允许动作可直接找到；不能统一变成失败或重跑按钮 |
| V2-11 | 操作节点文本、数值、下拉，删除键编辑文本 | 无误拖动、误删节点或滚轮误缩放；键盘可聚焦字段 |
| V2-12 | 两种桌面视口下打开 Details、预览及记录 | 主画布仍可工作；顶部执行动作持续可见；没有遮挡关键控件 |
| V2-13 | 上传期间换输入/删节点/换模板 | 旧响应不回填新对象；失败可恢复；不出现幽灵绑定 |
| V2-14 | 保存/加载草稿及显式载入历史配置 | 保存范围如实表达；不会静默丢失输入或未应用编辑 |
| V2-15 | 尝试将数据线接到参数字段 | 字段无伪 pin；不产生参数引用或隐式转换 |

CPU 路径、参数真实执行、输入完整性、预览/历史来源和常见错误恢复属于交付必要验收。真实模型切换与资产结果必须单独记录实际服务/GPU 验证；未运行时明确写未验证，不能以 CPU 或 FakeBackend 宣称真实资产流程通过。全部 v2 目标未达成时应按项标注剩余内容，不能将局部组件迁移报告为完整重设计完成。
