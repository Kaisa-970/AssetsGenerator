# 节点工作区 v2 实施与验收计划

2026-09-24。用户明确否定上一轮“提示收口”作为产品交付，要求面向公司内部资产流水线的节点工作台。
目标不是复刻 UE 外观，而是将输入、节点配置、执行、结果查看组织到同一工作区。

## 交付要求

- 输入节点能直接提供图片、mask、文本；使用实际 Artifact 绑定，上传不启动模型。
- 算子节点能直接选择兼容模型和编辑参数；完整 Details 与节点控件共享同一状态。
- 连线仅用于真实 OperatorSpec 数据端口；参数属性不能伪装成可连接端口。
- 顶部固定运行入口，后台状态与所选运行明确；不要求切到另一页填写已有输入。
- 选中节点在停靠预览区显示对应输出、状态和来源，不能遮住画布。
- 模型目录、添加节点、连线诊断、保存加载、错误定位和历史查看组成一致流程。
- 参数未应用、上传未完成、编译不通过等情况给出就地原因，并继续遵守已授权预检/幂等/来源核验。

## 开发流程

产品设计定义完整目标；状态架构审查确认唯一数据源；并行开发节点UI和执行交互；主agent集成。
按搭建与迭代任务验证，不仅验证按钮存在。至少覆盖从空白建立图片处理流程、图片+文本分割配置、切模型、运行到节点、保存加载和历史结果查看。
浏览器真实CPU闭环、针对性契约测试、独立review、截图检查与完整回归都属于交付门槛。
设计文档不是完成证据；未覆盖的目标继续实施，不能以局部绿测宣称目标实现。
