# DA3-Base 多帧资源验证 v1

日期：2026-09-17。范围：固定配置下的 4/8/16 帧串行资源 smoke。

## 输入与方法

使用 DA3 官方仓库 revision `3d835ec1a5802d64a8b8b15f817a1ab54809bfe4`
的 `assets/examples/robot_unitree.mp4`。视频 SHA-256：
`99bc274f7613a665c6135085fe01691ebfaa9033101319071f37c550ab21d1ea`。

视频容器报告 175 帧，OpenCV 顺序解码得到 174 帧，因此以实际解码帧为准。
从整个片段均匀选取 16 帧池，再分别均匀选 4、8、16 帧；各组并非两两嵌套。
输入分辨率为 1024×576。抽帧只是仓库外验证脚本，不构成 Core 的 Video 输入支持。
视频含潜在动态内容，不能用于声称静态物体几何精度或多帧带来的质量提升。

复用既有 DA3 环境和 DA3-Base 本地 snapshot，process_res=392，其余配置同
[双帧 smoke](da3-frontend-smoke-v1.md)。每组使用独立 Worker 进程和 Artifact Store，
串行运行一次；4 帧因耗时偏高额外复跑一次。总耗时包括身份摘要、输入准备、Worker 和 Core 输出校验；
模型加载与推理耗时单独记录。PyTorch allocated/reserved 峰值不是整卡显存用量。

证据位于 `<DATASET_ROOT>/da3-frame-scaling-v1/`：`source.json`、
`prepare.py`、`run.py`、`input-*.json`、`result-*.json`、`run.log` 和 `store-*/`。

## 结果

硬件为 RTX 5060 Laptop（8151 MiB），运行前整卡占用约 2932 MiB。
各组相机、原图尺寸深度、点云均通过 Core 端口和 frame/unit 一致性检查。
模型实际处理尺寸均为 392×224。

| 帧数 | 结果 | 总耗时 / s | 加载与推理 / s | allocated / MiB | reserved / MiB | 点数 |
|---|---|---:|---:|---:|---:|---:|
| 4 | pass | 80.920 | 18.329 | 1081.67 | 1442.00 | 118022 |
| 8 | pass | 7.187 | 2.333 | 1465.64 | 2086.00 | 118034 |
| 16 | pass | 7.621 | 2.600 | 1648.13 | 2234.00 | 118034 |
| 4（复跑） | pass | 55.184 | 17.294 | 1081.67 | 1442.00 | 118022 |

本配置下 16 帧未出现 OOM；这不是最大容量或更高分辨率的承诺。
首组 4 帧耗时高于后两组，因此额外复跑并保留原始记录。
未对系统负载、文件缓存或初始化耗时做隔离归因，不能从这些单次值推断吞吐随帧数变化的规律。
点云受置信过滤和确定性抽样限制，点数相近不表示几何质量相同。

Core 在提交前已完成 281 项测试、Ruff、mypy 和构建检查；本轮继续执行的是真实 GPU
资源验证，未修改运行时代码。
