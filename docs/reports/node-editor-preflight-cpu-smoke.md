## 实际操作与证据

1. 打开页面，模板标记 `CPU · 无需模型 · 配置可执行`。
2. 点击默认 CPU 模板并确认替换；自动编译并跳入运行页，无需手动编译或切换页签。
3. 默认浏览器上传，选择图片后显示本地缩略图及未执行模型的说明。运行列表仍为空。
4. 点击“启动新运行 · 检查执行范围”，真实调用准备输入与预检接口；界面显示 `encode · 将执行`。此时再次读取运行列表仍为空。
5. 点击“确认执行上述范围”，唯一一次 POST `/api/runs` 携带精确 `input_refs`、`preflight_digest` 和幂等 key。
6. encode 完成后点击图片预览，图片成功解码且 naturalWidth=1024。
7. 刷新页面，再读运行列表和 BuildRun：仍仅一个运行，BuildRun 与完成时逐字段相同。

运行：`dag_eedae1b7dfa24dbbb158a785cf66b8a5`；encode succeeded，只有一次 attempt。服务关闭后独立取得仓库锁，完整输出证据闭包校验通过；输出与输入 RGB 像素完全相同。浏览器无 pageerror。服务正常退出，确认随机端口已关闭。

这条路径还包含模板替换确认和独立预检确认；按实际显式动作拆分并计入打开页面，超过六步。相较上轮减少了手动编译、切换运行页和选择上传来源，但不宣称已经达到产品主路径点击预算。
